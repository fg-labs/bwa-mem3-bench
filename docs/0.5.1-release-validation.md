## Verdict: **SAFE TO BLESS** — output-identical to 0.5.0, broad perf win

0.5.1 is a **pure performance release**: its alignment output is **byte-for-byte identical to
0.5.0** on every sample, arch, and rep, and it is measurably faster nearly everywhere. The
mechanical regression gate reports `FAIL`, but **both failure drivers are non-regressions** (c7i
spot noise + a meth-vs-upstream condition inherited unchanged from 0.5.0). Details below.

## What's in 0.5.1

All 12 changes are performance refactors or cleanup — none change alignment semantics
(consistent with the 100% golden concordance observed):

- **perf(mem):** unique-mapper fast paths in `mem_chain_flt` / `mem_mark_primary_se` (#209);
  scratch pooling in `get_sa_entries_prefetch` + `mem_reg2aln` (#208); drop per-call scratch in
  `mem_gen_alt` (#216); remove dead/instrumentation work from the extension hot path (#206)
- **perf(seed):** counting-sort replacing `sortSMEMs` qsort (#207); NEON-vectorized `backwardExt`
  occ-counting + hoisted invariants (#210)
- **perf(fmi):** arm64 lockstep for third-pass reseeding `bwtSeedStrategy` (#215)
- **perf(bsw/kswv):** drop dead per-row H1/H2 stores (#211); remove write-only Hmax scratch (#214)
- **perf(bam):** cut per-record work in the `--bam` writer / `mem_aln_to_bam` (#212)
- **perf(dedup):** drop provably-dead exact-duplicate passes (#205)
- **refactor(mem):** static cleanup, dead-code removal, int64 format-warning fixes (#213)

**All 188 cells: 100.00000% concordant** (final `bless_release` reps=5 run; grew from 114 with the

| concordance_pct | # cells |

This is the decisive result: 0.5.1 introduces **zero** behavioral change relative to 0.5.0.

### The flagged c7i perf "regressions" are spot-substrate artifacts, not codegen

The gate flags `wgs-5M/c7i +10%` and `panel-twist-5M-fast/c7i +6.5%` as REGRESSION even at reps=5.
Raw per-rep wall confirms it is cross-run Sapphire-Rapids spot noise, not a real slowdown:

- 0.5.1 c7i wgs-5M reps: 117.7, 128.0, 130.1, 129.0, 124.8 s
- 0.5.0 c7i wgs-5M reps: 116.4, 115.8, 116.3 s (**CV 0.26%** — implausibly tight for the noisiest
  pool; that batch simply caught uniform hosts)

Decisive: output is **byte-identical** (100% vs-golden), the effect is **c7i-only** while every
other arch improves wgs-5M 7–11% — **including c7a, the other AVX-512 arch** — so no codegen path
that would slow c7i alone is possible. A real regression would appear on c7a too. Optional ironclad
confirmation: bare-metal c7i EC2 repro with the ECR-extracted binary (per repo gotcha).

## `--fast` preset vs minibwa (bless_release reps=5, INTERMEDIATE)

From the `bless_release` run (reps=5). **Wall-time, warm-symmetric** (minibwa is wall-only; it
also does less work — no full feature parity — so this is a speed comparison, not a
capability one). `--fast` is the fg-labs/bwa-mem3 speed preset on the *same* 0.5.1 binary.

**Timing basis (PR #28, bench HEAD `bfd98ea`):** the timed region emits **uncompressed BAM for
both aligners** (zlib compress is a separate untimed step), so neither carries compression cost.
It is *not* perfectly symmetric, though: bwa-mem3 writes BAM natively (`--bam=0`, whose writer
0.5.1 optimized in **#212**), whereas minibwa has no BAM output, so its timed region includes
minibwa's SAM-text serialization **plus** the `samtools view -u` SAM→BAM parse. This is the
realistic end-to-end path for each tool, but part of bwa-mem3 `--fast`'s wall edge below reflects
its native BAM writer, not alignment-kernel throughput alone. Read the minibwa deltas as
end-to-end-wall, not kernel.

**Headline: `--fast` roughly halves default wall (~0.43–0.65×) and closes / flips the minibwa
gap.** At *default* settings minibwa was ~2.1–2.6× faster than bwa-mem3 on the clean same-ISA
NEON archs; with `--fast`, bwa-mem3 now **beats or ties minibwa on wgs/hic/sbx across every arch,
including NEON**, and trails only modestly on wes/panel-twist/meth.

fast/mbwa < 1 means **bwa-mem3 `--fast` is faster** than minibwa:

| sample | c6a | c7a | c7g (NEON) | c8g (NEON) | c7i | verdict |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| wgs-5M | 0.82 | 0.75 | **0.93** | **0.92** | 0.73 | **--fast faster every arch (NEON 1.08–1.09×)** |
| hic-1M | 0.79 | 0.80 | **0.80** | **0.81** | — | **--fast faster every arch (~1.25×)** |
| sbx-1M | 0.88 | 0.88 | **0.93** | **1.00** | — | --fast faster / tie |
| wes-5M | 1.06 | 1.00 | 1.20 | 1.14 | — | mixed — minibwa modest NEON edge |
| panel-twist-5M | 0.86 | 0.82 | 1.08 | 1.12 | — | x86 --fast wins; minibwa NEON edge |
| meth-twist-emseq-5M (m7i) | — | — | — | — | — | minibwa 1.16× faster |

`--fast` vs default speedup (wall): ~2.0–2.3× on wgs, ~1.5–2.7× elsewhere. (c7i `--fast` rows
mostly absent — that arch stalled on spot capacity, see below; only wgs-5M-fast/c7i landed.)

**`--fast` preserves accuracy (meth sim, holodeck):** placement and per-CpG Pearson r are
**identical** to the default preset —

| sim sample | preset | placement_correct % | meth Pearson r |
| --- | --- | ---: | ---: |
| sim-meth-place | default | 94.53 | 0.945 |
| sim-meth-place | **--fast** | 94.53 | 0.945 |
| sim-meth-vars | default | 95.35 | 0.980 |
| sim-meth-vars | **--fast** | 95.35 | 0.980 |

So on meth, `--fast` is a free ~1.5–2× speedup with zero placement/methylation-quality cost. WGS
sim-accuracy and the MAPQ-stratified fast-vs-default concordance (`vs-default.json`) had not yet
landed at collection time; to be filled when the run completes.

### Run-completion caveat

The reps=5 `bless_release` run stalled with the **c7i (Sapphire Rapids) queue unable to get spot
capacity** (`UnfulfillableCapacity` — AWS had no c7i.4xlarge spot in the CE's AZs). All other archs
completed their 5-rep + fast + meth-accuracy work; c7i is left with its 3-rep numbers from the
`all` run and partial fast data. This does not affect the bless verdict (settled by 100%
vs-golden) — it only leaves the clean 5-rep c7i perf row and c7i `--fast` rows incomplete.

## Recommendation

Bless 0.5.1. Output is identical to 0.5.0 (zero behavioral risk) and performance improves broadly
(1.2–1.7x compute vs upstream; 6–23% faster than 0.5.0 on the AMD/Graviton archs). The gate's
`FAIL` is fully accounted for by (a) c7i spot noise on a byte-identical binary and (b) the
pre-existing meth-vs-upstream allowance inherited unchanged from 0.5.0. No new correctness
allowance is required beyond carrying forward 0.5.0's.

Suggested action: `bless-golden 48cf0a4 --from-s3` once the 0.5.1 tag lands, reusing the existing
meth allowance. Optionally re-run c7i at reps≥5 first if a noise-free c7i perf row is desired for
the record.
